# Desktop Modification

Status: accepted by the user's instruction “so do it, mod”. Supersedes the unresolved integration choice in ADR 001.

Codex Usage Bar patches the existing local Codex desktop composer. It occupies a row above the intact native Goal/utility/composer group, outside the scrolling transcript. Native utility positioning remains unchanged; its measured overflow is reserved in the composer stack. Usage follows the native rail width and inset. It uses the host's React instance and account/model quota state; Context uses the selected conversation's existing token-usage selector. No new server, account credential handling, or message submission path is introduced.

Current order is Weekly, Files changed, Token speed, Context. No reset icon or five-hour quota is rendered. Five-hour quota remains future work. The bar inherits `--codex-chat-font-size` and native theme tokens. Measured content fit shrinks the weekly progress track to a visible 16 px minimum, then reduces spacing and text; pills never wrap. A later user correction supersedes the shared outer frame: each chip uses the existing Files changed surface tokens and rounded-3xl radius. The row has no shared background, border or outer padding. Weekly uses semantic normal/yellow/red tokens, with yellow above 10% through 20% remaining and red at 10% or below. Compact labels/countdown shorten in stages; further constraints hide the speed icon and Weekly label.

The existing in-progress Files changed control is portaled into the bar immediately after Weekly, scoped to the selected host/chat. Its live counts, tooltip, native diff-opening action and React context remain owned by Codex. Plans, environment progress and additional native portals retain their upper location. If the bar is absent, Files changed falls back to its native location. Completed transcript diffs remain unchanged. The usage row adds no outer padding and inherits the existing 8 CSS px gap to the input.

Speed is explicitly approximate. A read-only observer receives the host ID, event name, token counts and timestamps, retaining no message contents. It divides output tokens by measured model-wait seconds over up to ten responses, following Hermes’s weighted aggregate. It includes prefill and first-token waiting and subtracts the union of observed tool intervals. Desktop lifecycle events are not provider API timestamps, so speed stays approximate. A mid-turn attach without an observed start remains unknown. Account changes and counter resets clear observer state. The former first-to-last-delta estimator is superseded because it could overstate speed. Weekly shows remaining quota, matching native “% left” wording; the track fills the same remaining value. Only the core account weekly quota is displayed.

The patcher accepts one tested app version and exact baseline archive hash, validates unique source anchors, preserves unrelated archive entries and unpacked modules, regenerates archive integrity metadata and dynamically synchronizes the enabled native dictionary digest before dependency-ordered signing, and prepares a candidate before touching the installation. Retain one Safe Build and one New Build locally, excluded from Git. The installer refuses an incompatible or changed installation and retains the previous verified mod in New Build for transactional recovery. The protected Safe Build remains unchanged and is never an automatic fallback that removes the mod. No full vendor app code is published.

Local app modification changes the vendor signature. Updates can overwrite the patch; a changed version must be inspected before rebuilding. Visual fixture tests validate layout, while live account/chat integration is a separate acceptance check. The host app cannot be inspected with the computer-use tool in this session; do not bypass that restriction through another automation channel.

## Accepted three-stage fitting

At full width, Weekly's progress track starts at 100 logical CSS px and receives 70% of the spare width after natural content and base spacing. The remaining 30% is shared equally per object-to-object gap and horizontal end inset. Pill growth is proportional to its visible space count, so Weekly, speed and Context retain equal resulting gaps. Native Files changed keeps its existing internal interaction/layout.

- Stage 1 first tightens spacing and shrinks the track only as needed toward 16 px. If more room is required, remove `left` and reduce the countdown to its largest unit: `6d 8h` becomes `6d`, while an hours-only remainder stays `8h`.
- Stage 2 changes `token/s` to `tok/s` and `Context` to `Ctx` together and hides `Weekly`. If necessary, hide the speed icon and tighten spacing next.
- Stage 3 caps text at 14 px and 12 px only as needed. Below the irreducible readable width, the local shell scrolls horizontally without wrapping or overflowing the page.

All visible values and the progress fill remain intact. Fitting reacts to text, native diff counts, font, width and zoom. Fuller states restore only when at least 8 logical CSS px of clearance is available, preventing boundary flicker. Usage follows both Goal rail edges using converted logical measurements, retaining the native Goal inset when no rail is visible; native Apps/Goal/composer geometry remains unchanged.


The latest user-approved chat/composer-width thresholds are Stage 1 at 620 px, Stage 2 at 580 px and Stage 3 at 490 px, all logical CSS pixels. Native composer width determines these triggers, independently of whole-window width and the narrower Goal/Usage rail. Stage 1 removes `left` and extra countdown units; Stage 2 pairs compact token/context labels and hides Weekly; Stage 3 applies readable text caps. Content fitting still prevents wrapping, and restoration has an 8 px buffer. At every fit level, width left after natural content and minimum/standard spacing is split 70% to the track and 30% equally per object gap and horizontal end inset. The repository publishes original source, installer, tests and documentation; app binaries, extracted vendor assets and local operational data are excluded.
